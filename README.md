# WEMEET QA Portfolio

기능이 작동하는지보다, 사용자가 왜 다시 돌아오는지를 먼저 확인하는 태도를 보여주는 프로젝트입니다.  
WEMEET은 단순 퀴즈 서비스를 넘어 `사용성`, `기능 적합성`, `성능`, `보안`을 함께 설계한 QA 중심 학습 플랫폼 사례로 정리했습니다.

## Why This Project Matters

초기 기능은 정상적으로 동작했지만, 사용자가 문제를 푼 뒤 다시 돌아오지 않는 구조였습니다.  
저는 이를 단순 기능 완성으로 보지 않고, 서비스 품질의 핵심인 `지속 사용성 부족` 문제로 판단했습니다.

팀 내에서는 그대로 출시하자는 의견도 있었지만, 저는 전면 개편이 아니라 핵심 기능을 먼저 시범 구현해 학습 경험 차이를 검증하자고 제안했습니다.  
이 과정은 QA가 단순히 오류를 찾는 역할이 아니라, 사용자 관점에서 품질 문제를 정의하고 증거로 설득하는 역할이라는 점을 보여준 경험이었습니다.

## QA Perspective

- `사용성`: 문제를 풀고 끝나는 흐름에서, 오답 이후 관련 개념까지 자연스럽게 이어지는 학습 흐름으로 개선
- `기능 적합성`: 작동 여부가 아니라 사용 목적에 맞는 구조인지 검토하고 서비스 방향을 재정의
- `성능`: 데이터 연결 관계가 복잡해진 뒤 쿼리 실행 계획을 분석해 병목 구간과 접근 경로를 재설계
- `보안`: 사용자별 학습 기록과 오답 패턴이 서로 노출되지 않도록 접근 권한 분리 구조를 설계

## Key Contributions

- 수만 건의 전문 지식 데이터를 분류할 수 있는 데이터 모델 설계
- 오답 패턴 기반 개념 연결 구조를 제안하고 시범 구현으로 팀 합의 도출
- 조회 속도 저하 이슈에 대해 인덱스 추가에 그치지 않고 실행 계획 기반으로 병목 분석
- 사용자별 데이터 접근 권한과 노출 가능성을 검토해 보안 요구사항을 설계에 반영
